## 要件

### 目的

- Affinity で使える、写真の光源に光芒（クロスフィルターのような光の筋）を描くフィルター。（指定）
- 明るい点すべてではなく、周りの様子を見て光源らしい場所にだけ光芒を描く。（指定）
- Photoshop 互換のフィルタープラグイン（`.8bf`）として作り、Adobe の Photoshop Plug-in SDK を使う。（同意）

### 名前

- Hikariuni（光 hikari ＋ ウニ uni。光芒がウニのトゲのように広がることから）。（指定）
- 既存の製品を参考にしたとわからない名前にする（権利のため）。（指定）
- 既存の製品の名前を、リポジトリ（コード・ドキュメント・コミットメッセージ）に一切書かない。（指定）

### 開発環境と構成

- Visual Studio 2026 の `.slnx` ＋ `.vcxproj` でビルドする。CMake は使わない。（指定）
- プロジェクトごとにフォルダを分ける（`src/hikariuni.slnx`、`src/<プロジェクト名>/<プロジェクト名>.vcxproj`）。（指定）
- Photoshop Plug-in SDK はリポジトリに入れず、環境変数 `PHOTOSHOP_SDK_PATH`（SDK の `pluginsdk` フォルダ）で参照する。（指定）
- SDK のヘッダーは `<>` で読み込む。（指定）
- C++23 で書く。（指定）
- AVX2 までの最適化をしてよい。（指定）
- 対象は Windows x64 だけ。（同意）
- テストは GoogleTest。Visual Studio から入れる NuGet パッケージを使い、vcpkg は使わない。（指定）
- C++ は `.clang-format` で整形する。（指定）
- 決まった仕様は `docs/spec.md` に書き、仕様を変えたら更新する。（指定）

### 機能

- 光芒だけを書き出すモード（光芒のみ出力）。レイヤーに透明度があれば透過で、なければ黒背景で書き出す。（同意）
- プレビューのクリックで光源を追加し、Alt+クリックで外せる。（機能は同意、操作は指定）
- 手動で追加した光源の大きさは固定にせず、その場所の光に見合った大きさにする。（同意）

- スライダーの値を数値でも入力できる。（指定）

- プレビューを拡大して細部を確かめられる。（同意）

  - Ctrl+ホイールで拡大縮小し、中ボタンのドラッグで移動する。

### ビルド

- Visual Studio 2026（MSVC、PlatformToolset `v145`）の `.slnx` ＋ `.vcxproj`。構成は Debug / Release、プラットフォームは x64 のみ。
  - コマンドラインでは VS 2026 の MSBuild: `MSBuild src\hikariuni.slnx -restore -p:RestorePackagesConfig=true -p:Configuration=Release -p:Platform=x64`（`-restore` 以降は NuGet パッケージの復元）
- Photoshop Plug-in SDK はリポジトリに含めない（Adobe のライセンスのため）。
  - 環境変数 `PHOTOSHOP_SDK_PATH` に SDK の `pluginsdk` フォルダを指定する。未設定ならビルドをエラーで止める。
  - 使うのは `photoshopapi/photoshop`、`photoshopapi/pica_sp`、`samplecode/common/includes` のヘッダーと `samplecode/resources/Cnvtpipl.exe` だけ。
  - SDK ヘッダーが Windows 用の分岐を選ぶよう `WIN32=1` を定義する。
- C ランタイムは静的リンク（`/MT`、Debug は `/MTd`）。配布先に VC++ ランタイムを要求しない。
- ダイアログは comctl32 v6（今の見た目のコントロール）を使う。DLL のマニフェストに依存関係を入れ、`ISOLATION_AWARE_ENABLED=1` で有効にする。
- 言語は C++23（`LanguageStandard` = `stdcpp23`、VS 2026 では `/std:c++23preview`）。プラグインもテストも同じ。
- AVX2（`/arch:AVX2`）でビルドする。動かすには AVX2 対応の CPU（Intel Haswell・AMD Excavator 以降）が要る。
- 重い処理（Apply とプレビューの合成）は画像を 64 行ずつの帯に分け、`std::execution::par` で並列に処理する。
- ソースは UTF-8（`/utf-8`）、警告レベル `/W4`。SDK ヘッダーは外部ヘッダー扱いで警告を出さない。
- 出力は `src/x64/<構成>/hikariuni.8bf`。
- テスト: GoogleTest。VS の Google Test プロジェクトテンプレートと同じ NuGet パッケージ `Microsoft.googletest.v140.windesktop.msvcstl.static.rt-static` 1.8.1.8（静的ライブラリ・静的ランタイム、`gtest_main` 付き）を `packages.config` で使う。
  - パッケージは `src/packages/` に復元される（git 管理外）。
  - `hikariuni.test` はビルド後に自動で実行され、失敗するとビルドも失敗する。VS のテストエクスプローラーからも実行できる。

  - 新しい SDK が使う JSON 形式（リソース `JSON_PIPL`）は Affinity が読めず、プラグインとして認識されない。
- 生成の流れ（`hikariuni.vcxproj` のカスタムビルド）: `hikariuni.r` → `cl /EP` → `Cnvtpipl.exe` → 中間フォルダの `hikariuni.pipl` → `hikariuni.rc` で `#include`。

### フィルター処理

1. `filterSelectorStart` で画像全体（`filterRect`）・全プレーンを一度に要求する（タイル分割なし）。
   - ホストが `bigDocumentData` を持っていれば 32bit 座標を使う。
   - `filterRect` が空なら何もしない。
2. 長辺 2000px に縮小した検出用画像を作る（面積平均）。
3. 前回のパラメーターを読み込み、ダイアログを出す。キャンセルなら `userCanceledErr` を返して何もしない。
4. OK なら設定を保存し、光源を検出・配置（手動の追加・除外を反映）して、元画像に光芒を加算して書き出す。
   - 「光芒のみ出力」なら元画像を使わず光芒だけを書き出す（ライブ編集の代わりに、複製したレイヤーに使って後から不透明度・マスク・位置を調整する）。
     - 透明度を書き換えられれば透過: 不透明度 = 光の強さ（色チャンネルの最大、上限で止める）、色 = 光 ÷ 不透明度。通常の合成で「色 × 不透明度 = 光」になり、スクリーン・加算で重ねた結果は黒背景版とまったく同じになる。
     - 透明度プレーンがない、またはホストが透明度を保護している（`filterCase` が protected transparency の 2 ケース）なら黒（0）に加算する（黒背景。透明度はそのまま）。
   - メモリを抑えるため、光芒は 64 行ずつの帯ごとに浮動小数点のバッファに描いてから加算する（帯は並列に処理する）。
   - 色プレーンにだけ加算し、上限（8bit は 255、16bit は 32768）で止める。透明度プレーンはそのまま。
   - グレースケールは光の RGB の平均を加算する。
- 対応: RGB / グレースケール、8bit / 16bit。16bit は Photoshop の仕様どおり 0〜32768。それ以外のビット深度（32bit など）は `filterBadMode` を返す。（要確認）
- 選択範囲があるときは、選択範囲の外接矩形の中で検出・描画し、選択範囲外はホストが元に戻す（doNotWriteOutsideSelection）。
- 透明な部分には光芒が見えない（色だけを加算し、透明度は変えないため）。（要確認）
- About はメッセージボックスを表示する。
- Affinity（Canva 版、Windows）で動作を確認済み（2026-10-15。光芒の描画、プレビュー、ダイアログのサイズ変更・数値入力を含む）。

### ダイアログ

- 8bf の仕組みでは、プラグインはホストから画素を受け取って書き戻すだけで、UI はプラグインが自前で出す。Affinity のパネルに UI を出したり、ライブフィルターのように後から再編集したりはできない。
- 左にプレビュー（右と下にスクロールバー）と操作の説明（1 行）、右にパラメーターの行（名前・数値入力・スライダー）を並べる。下に「初期値に戻す」ボタン、「光芒のみ出力（透過）」チェックボックス、「全体表示」ボタンと拡大率（%）、テーマ切り替えボタン、「OK」「キャンセル」ボタン。
  - 光芒のみ出力をオンにすると、プレビューは光芒だけを表示する（透明な部分は黒で見せる）。
  - 「初期値に戻す」はパラメーターと光源の手動の追加・除外を元に戻す（表示の拡大率・位置はそのまま）。（要確認）
- ウィンドウはサイズ変更・最大化できる。パラメーター欄の幅は固定で、残りをプレビューに使う。テンプレートの大きさ（620 × 325 ダイアログ単位）より小さくはできない（画面のほうが小さければテンプレートの大きさのまま）。
  - DPI が変わってダイアログのフォントが変わったら、自分で作ったパラメーターの行にも付け直す。
- 数値入力: フォーカスが外れたときか Enter で確定する（数値入力中の Enter ではダイアログを閉じない）。範囲内に収めて刻みにそろえ、数値でない・有限でない（nan、inf）なら元の値に戻す。
- プレビューの表示（操作は Affinity に合わせる）:
  - 開いたときは全体表示（画像全体が表示枠に収まる拡大率）。全体表示中はウィンドウの大きさを変えても全体表示のまま。
  - Ctrl+ホイール: カーソルの下の点を動かさずに拡大縮小する（1 目盛り 1.25 倍、全体表示の半分〜3200%）。
  - ホイール: 上下に移動、Shift+ホイール: 左右に移動（1 目盛り 80px）。
  - 中ボタンのドラッグ: 移動（移動カーソル）。スクロールバーでも移動できる（矢印 80px、ページは表示枠ぶん）。
  - 「全体表示」ボタン: 全体表示に戻す。
  - 画像が表示枠より小さい向きは中央に置き、大きい向きは画像の端で止める。100% を超える拡大はドットのまま（ニアレストネイバー）。
- プレビューの合成:
  - 元画像全体を表示倍率（100% まで）に縮小し、光芒を合成したもの（合成キャッシュ）を持つ。表示の移動・拡大縮小はキャッシュの見える部分を描き直すだけにして速くする。
  - キャッシュの画素数は 2400 万画素までに抑える（それを超える巨大画像は、100% でもキャッシュから少し拡大して見せる）。
  - キャッシュの大きさが変わる（100% 未満で拡大率を変えた）ときだけ縮小からやり直す。それまでは今のキャッシュを拡大縮小して見せる。
  - 値を変えたときは、キャッシュに光芒を合成し直す。明るさ・コントラスト・最大サイズを変えたときだけ光源の検出もやり直す。
  - 再計算はタイマー（15ms）で後回しにし、連続した変更は 1 回にまとめる。スライダーのつまみの描画を待たせないため。
  - ちらつき防止: プレビューは画像の外側だけを背景色で塗る。ドラッグ中のスライダーには位置を設定し直さない。
- 光源の手動の追加・除外（プレビュー画像の上でのマウス操作。画像の上では十字カーソル）:
  - クリック（動かさずに離す。4px 以上動いたらクリックとみなさない）: その位置に光源を追加する。検出用画像でその周り 2px のうち最も明るい画素を起点にする。
    - 強さ: 検出と同じ測り方のエネルギー。起点から `C ≥ コントラスト` の画素を 4 近傍でたどった `C` の合計（検出の除外条件は使わない）。起点の `C` がコントラストに届かないときは、閾値を起点の `C` まで下げてたどる（暗い光は小さい光源になる）。クリックした時点の設定で測り、後で設定を変えても測り直さない。配置で最低 0.05 にする（コントラストのない場所でも見えるように）。（要確認）
    - 色: 起点の画素の色（最大チャンネルが 64 未満なら白）。
  - Alt+クリック: 画面上 12px 以内で最も近い光源を外す。手動で追加した光源なら消し、自動の光源ならその位置を除外リストに入れる。
  - 除外は位置で覚え、配置のたびに除外位置から 5 単位以内の自動の光源を外す（検出をやり直しても同じ光源が外れる）。
  - 手動の追加・除外は画像ごとのものなので、設定ファイルには保存しない。（要確認）
- 配色（テーマ）: ダーク / ライトをボタンで切り替える。
  - 既定はダーク（Affinity の既定に合わせる）。（要確認）
  - Affinity のテーマに自動で合わせることはしない（8bf の API ではホストのテーマを知る手段がなく、Affinity の設定ファイルの形式も公開されていない）。
  - 切り替えたらすぐ保存する（キャンセルしても残る）。（要確認）パラメーターとは別に保存し、「初期値に戻す」では変えない。
  - ダークの作り方: タイトルバーは `DWMWA_USE_IMMERSIVE_DARK_MODE`、ボタン・スクロールバーは Windows のダーク用テーマ `DarkMode_Explorer`、数値入力欄は `DarkMode_CFD`（どちらも公開 API ではないが、エクスプローラーなどが使っている）、ダイアログ・文字・入力欄・スライダーの背景は `WM_CTLCOLOR*` で色を付ける。
  - テーマ付きのチェックボックスは文字色を変えられないので、ダークのときはカスタムドローでチェックの箱（テーマの部品）と文字を自分で描く。
  - 色（ダーク）: 背景 RGB(50, 50, 52)、文字 RGB(228, 228, 228)、入力欄 RGB(34, 34, 36)、プレビューの余白 RGB(38, 38, 38)。ライトは Windows の標準色で、プレビューの余白だけ RGB(190, 190, 190)。
- 表示は日本語だけ。（要確認）
- 設定は `%APPDATA%\Hikariuni\hikariuni.ini` に保存する。
  - `[params]`: OK したパラメーター（キーはパラメーター表のキー）。次回の初期値にし、読み込むときは範囲内に収めて刻みにそろえる。光芒のみ出力は `raysOnly`（0 / 1）。（要確認）
  - `[window]`: 閉じたときのウィンドウの大きさ（`width` / `height`、px。最大化中は元の大きさ）。次回は画面の中央にこの大きさで開く。（要確認）
  - `[ui]`: `dark`（1 = ダーク、0 = ライト）。

### 光芒アルゴリズム

`src/hikariuni/effect.cpp`。

#### 光源の検出

1. 長辺 2000px に縮小した画像で検出する。
2. 輝度 `L = 0.2126R + 0.7152G + 0.0722B`（0〜255）。
3. 局所コントラスト `C = L − 周囲平均`。周囲平均は半径 `R = max(3, round(最大サイズ × 1.5))` の箱平均（積分画像で計算）。最大サイズ（px）は `最大サイズ × 検出用画像の短辺 / 1000`。`L < 明るさ` の画素は `C = 0`。
4. `C ≥ コントラスト` の画素を 4 近傍で連結し、ひとつの光源候補にする。
5. 次の候補は除外する。
   - 等価直径 `2√(面積/π)` が最大サイズを超える（花・雲・天の川の塊など）。
   - 縦横比が 3 を超える（共分散行列の固有値比が 9 を超える。物の縁や線）。
   - 周囲（半径 R の正方形）に、候補の平均輝度 × 0.85 以上の画素が 10% を超えてある（花びらの先端など、大きな物体の一部）。
6. エネルギー = 候補内の `C` の合計。エネルギーの降順に並べる。
7. 色 = 候補画素の平均色を、最大チャンネルが 1 になるよう正規化したもの。

#### 配置

1. 強い順に、採用済みの光源から最小間隔以上離れているものだけを、最大個数まで採用する。
2. 除外位置から 5 単位以内の光源を外す。
3. 手動で追加した光源を足す。
4. 強さ `e` = エネルギー ÷ 検出した全候補のうち最大のエネルギー（検出が 0 個なら 1 で割る）。どの光源を外しても、ほかの光源の大きさは変わらない。手動の光源は、コントラストのない場所に置いても見えるよう 0.05 以上にする。
- 重み `wt = √e`（e は 0〜1 に収める）。

#### 描画（加算合成）

- 単位 `u = 短辺 / 1000` px。長さ・太さ・ハロー・最小間隔はこの単位で指定する。
- 不透明度 `a = min(1, 強さ × (0.3 + 0.7wt))`。光の明るさは `色 × 255 × a`。
- ハロー: 半径 `ハロー × u × wt` の円。中心 `0.6` 倍 → 縁で 0 へ線形に減る。半径 1px 未満なら描かない。
- 光芒: 角度から等間隔に本数ぶん。中心の幅 `太さ × u × (0.3 + 0.7wt)` で、先端に向かって幅 0 まで細くなる。長さ方向に 1 → 0.4（25% 地点）→ 0。
  - 幅方向の明るさ（中心線からの距離 s、その位置の半幅 h）は「くっきり」と「山形」を柔らかさで混ぜる。
    - くっきり: `clamp(h + 0.5 − s, 0, 1)`（縁は 1px ぶんのアンチエイリアス）。
    - 山形: `clamp(1 − s / (h × (1 + 柔らかさ) + 0.5), 0, 1)`。柔らかさ 1 で幅 2 倍・中心の明るさは同じ・合計の明るさはほぼ同じ。
    - `くっきり + (山形 − くっきり) × 柔らかさ`。柔らかさ 0 なら従来どおりのくっきりした縁。
  - 幅が 1px より細い部分は幅に比例して暗くする。長さ 1px 未満なら描かない。
  - 外接矩形全体ではなく、各行で光芒が届く範囲だけを調べ、RGB を 1 回でまとめて描く。
- 虹色（分散）: R・G・B の長さを R は `×(1 + 0.2 × 分散)`、G は `×1`、B は `×(1 − 0.2 × 分散)` にする。分散 0 なら元の色と同じになる。
